## 背景

T05、T07 标为 done 后复查发现以下缺口，由本任务修复：

- 新建草稿后编辑器无法上传图片，这条路径无法发布。
- 编辑已有合集时没有加载已有成员，保存会覆盖成员；不能排序、改简介、选封面。
- 编辑器缺少来源类型、作者、来源链接、模型版本、图片比例；图片不能排序，alt 不能编辑。
- 批量操作的失败原因在刷新时丢失。
- 首页提交筛选表单会丢掉已选标签。
- 详情页没有分享按钮；“加载更多”只跳转到下一页；手机端没有筛选抽屉。
- 上传页没有并发限制、逐项进度、失败重试、拖拽粘贴和批量默认值。
- 统计只收集，没有后台展示。

## 已知限制

- Lighthouse 跑在开发服务器上。生产构建会拒绝 `STORAGE_DRIVER=fs`，本机没有 MinIO，无法在生产模式下提供图片，所以没有记录性能分数，只看可访问性和 CLS。上线前应在预发环境（S3/TOS）上再跑一次。
- 本机上传必须让 Next 服务和 Worker 共用 `fs` 或 S3 存储；`memory` 存储下图片会在重启或跨进程后丢失。本机开发库里早期有 9 条内容因此丢图，已下线，属于本机数据问题。
- 编辑器有未保存修改时禁用上传，需要先保存。
- 中文标题生成的 slug 是 `p-xxxxxx`，没有语义；发布前可以手改，发布后锁定。
- 统计是粗略事件次数：不区分访客，超过频率限制、拦截脚本或关闭 JavaScript 的访问不计入。
- 分享的 E2E 只验证复制链接的回退路径，系统分享面板需要真机手动验证。
- 手机和平板宽度下，键盘灯箱、加载更多返回和后台发布流程没有 E2E，只在桌面宽度覆盖。
