## 数据层范围

迁移创建 18 张表：`admins`、`sessions`、`categories`、`tags`、`models`、`assets`、`prompts`、`prompt_tags`、`prompt_assets`、`collections`、`collection_prompts`、`upload_batches`、`upload_items`、`jobs`、`idempotency_keys`、`rate_limits`、`analytics_events`、`audit_logs`。

约束进入 SQL，而不只写在 TypeScript 里：状态枚举、唯一 slug 与 `normalized_name`、外键删除行为、公开列表部分索引，以及发布时 `published_at`、文本长度、来源 URL、40 万像素上限等检查。分类或模型被内容引用时不能删除。删除标签只删除关联。同一张图片可被多条内容引用，仍有引用时不能删除图片行。

`listPublishedPrompts` 只返回 `status = published` 且 `deleted_at` 为空的行，并按 `published_at DESC, id DESC` 排序。种子里的草稿不会出现在这个结果中。

名称规范化在 `normalizeName`：NFKC、去两侧空白、转小写。数据库另外要求 `normalized_name` 等于 `lower(btrim(normalized_name))`。

## 已知限制与后续差异

- 没有更早的迁移文件。升级覆盖是：空库执行迁移，再执行一次，迁移记录保持 1 条。
- 封面必须属于该条内容的图片列表，这是 T05 发布事务的规则，当前不是数据库约束。
- `assets.original_key` 是唯一对象键，`card_key` 和 `detail_key` 在处理完成前可空。技术设计里的私有源文件和去元数据后的公开原图如果必须分开存放，T04 需要新增迁移，不能改 `0000_init.sql`。
- 上传批次仍然只会指向新建草稿。T04 实现“往已有内容追加或替换图片”之前，要新增迁移保存已有草稿 id。
- 内容 slug 的生成规则留在后续写入流程。种子使用固定 slug。
- 登录、上传 Worker、后台和公开页面不在本任务内。
